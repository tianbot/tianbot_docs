# 提交成绩与查询排名

裁判产生结果后先保存在本机，再由选手手动提交到平台。请在 **2026 年 10 月 15 日 23:59（北京时间）截止前**完成提交并确认受理。

## 1. 确认本轮结果

正式跑满五个有效圈后，裁判显示已完赛并保存总用时。当前轮具备有效绑定、官方环境校验与赛道资格时，“提交成绩”按钮可用。

若计时中人工结束，裁判会保存未完赛结果；符合上报条件时同样可提交，但未完赛不能替代五圈完赛最佳成绩。

::: tip 先确认车辆停止
裁判锁定成绩并不会停车。按[停止车辆](./run-and-test#stop-car)结束独立跑圈程序并确认车辆静止，再处理提交和下一轮。
:::

## 2. 点击“提交成绩”

按钮会暂时显示“提交中”。等待事件记录返回：

- **“成绩已提交”**：平台已受理这条结果。
- **“成绩已确认（幂等重放）”**：平台之前已经受理同一条结果，本次确认没有重复新增成绩。
- **错误信息／“重试提交”**：尚需检查错误原因，不能当作成功。

如果本机还有其他未提交结果，按钮可能显示“提交下一条”。继续处理需要上报的记录，并核对平台历史；不要只提交一条就假定本地所有尝试都已上传。

提交使用裁判保存的完成圈数、总用时和本轮归属。选手不需要手工填写成绩、计算分数或运行往届 `upload.py`。

## 3. 到赛事平台确认

打开 [2026 iCAN 赛事主页](https://race.tianbot.com/e/2026-ican-ai)：

1. 查看本届仿真裁判排名赛段。
2. 在排名中找到自己的队伍。
3. 核对完成圈数和总用时。
4. 打开该队的历史成绩入口，核对收到的尝试及“当前最佳”。

主页约每 30 秒自动刷新，也可以点击“刷新成绩”。新提交没有马上显示时先刷新；较慢的完赛成绩不会替换已有最佳，所以当前排名时间可能保持不变。

仅有未完赛结果的队伍不会因此获得五圈完赛排名。未完赛记录和当前最佳的区别，以队伍历史与平台反馈为准。

**完整提交成功的依据是：裁判显示平台已受理，且平台中能查到本队对应记录。** 本地时间停止、结果文件存在或截图显示五圈，都不能代替平台回执。

## 4. 失败后使用原记录重试 {#retry}

网络异常时，结果仍保存在本地。恢复网络后点击“重试提交”；重启裁判也会恢复符合条件的待提交记录。

同一轮使用固定尝试编号重试。平台已收到但本机未收到反馈时，再提交会确认原回执，而不会生成重复成绩。不要更改尝试编号、圈数或用时来处理网络问题。

| 失败原因 | 如何处理 |
| --- | --- |
| 网络错误或服务暂不可用 | 恢复网络后重试原记录，仍需满足授权及提交窗口要求 |
| `SUBMISSION_NOT_OPEN` | 尚未开放提交，等待正式窗口 |
| `SUBMISSION_CLOSED` | 新成绩已不能受理，联系赛务确认；不能修改本机时间绕过 |
| 授权撤销、过期或凭证失效（401） | 联系赛务处理授权，再按要求重新绑定 |
| 赛段不可用或赛事配置异常 | 将具体报错提供给赛务，不要改绑其他赛事提交 |
| `IDEMPOTENCY_CONFLICT` | 同一编号对应不同内容；保留原记录及错误信息，联系赛务 |

截止之后，**之前已受理**的同编号、同内容请求，在凭证及赛段仍有效时可以确认原记录；**之前未被受理**的本地成绩则属于新成绩，不能因为是断网重试就绕过截止时间。请留出提交与核对时间。

## 5. 为什么结果只能本地保存

`local_only` 表示本轮可以用于练习分析，不能上传为正式成绩。常见原因有：

- 准备发车时没有有效绑定，包括当时无法核验绑定或设备身份。
- 使用了其他赛道。
- 赛道或车辆模型未通过官方校验。
- 开启了跳过模型校验的开发模式。
- 本轮环境改变或结果无效。
- 旧版本历史记录缺少本届需要的赛道证明。

请查看事件记录中的具体原因，修复环境后重新开始一轮。**绑定成功或更新环境不能将已经开始的本地练习补成正式成绩。**

## 6. 本地保存位置

默认成绩文件为：

```text
~/.local/share/tianbot-judge/results.json
```

它用于保存本机尝试、提交状态和平台回执。“清除本轮”只清理裁判当前状态，不删除这个历史文件。

排障时可以查看结果状态，但不要编辑文件中的圈数、时间、归属或校验字段。记录可能包含绑定信息，提供给他人排障前应避免暴露凭证；不要把整个目录上传到公开仓库。
